# 两篇全程监督稿怎样使读者一步步理解

这两篇由用户确认全程监督，是结构范例。取得的校样/刊版没有逐词修订归属；下面分析被采用的论证，不给共同稿件建立 Tang 个人词频。版本定位见 [source-notes.md](source-notes.md)。

## 疲劳跨域模态补全稿 U1

*Enhancing Fatigue Detection through Heterogeneous Multisource Data Integration and Cross-Domain Modality Imputation*。

引言有四个实质段落及三条贡献，其中长段承担多个相互依赖的句群：

| 读者需要弄明白什么 | 实际怎样回答 | 这一层为什么不能跳过 |
|---|---|---|
| 疲劳信息为什么有用？ | 从生理/行为信息接到预警、调度、干预与安全决策，再接到部署现场持续采集数据的需要 | “重要”有了具体使用目的，读者才理解采集限制的后果 |
| 已经有哪些处理能力？ | 先说不可靠传感器的后果，再介绍补全/合成及模态关系建模 | 先承认已有成效，才能公平界定仍未覆盖的条件 |
| 这些能力为什么没有结束本文的问题？ | 区分 reliability 与 accessibility；说明受限传感器的部署条件，进一步区分同域已有模态合成与目标域整模态从未观测 | gap 来自数据可用条件的差别，不能仅写“现实复杂”或“方法仍有不足” |
| 本文路径凭什么有可能成立？ | 共享模态反映同一潜在疲劳状态的直觉 → 共享空间提供桥梁 → 利用源域关系估计目标缺失模态 | 读者先懂为何可行，再看到框架与组件 |
| 这篇究竟证明到哪一步？ | 明示 proof-of-concept 与已有组件整合；评价受限传感配置下的框架可行性 | 贡献对象得到限定，避免把框架验证写成新算法或普遍部署保证 |

三条贡献分别落在问题设定、框架及可行性证据上。可迁移的是这些判断之间的依赖；其他研究不应自动继承模态缺失设置、组件或贡献数。

这是跨域补全论文，不能与后续 U-GAT 项目混为同一版本，也不能把后者的 mask、temporal graph 或新算法倒填进这篇论文。

## AIGC 综述 U2

*The Evolution and Future Perspectives of Artificial Intelligence-Generated Content*。

引言有七个实质段落：

1. 先说明 AIGC 是什么、影响哪些创作工作，给读者共同对象。
2. 从发展与数据生产的实际困难，解释为什么需要快速、可扩展且一致的内容生产。
3. 说明不同生成路线如何工作、能力受什么条件限制，以及能力扩展带来的新要求。
4. 引出跨阶段共同框架：综述怎样使不同路线可比较，以及它能帮助谁作什么选择。
5. 交代历史覆盖及技术进步与挑战的讨论。
6. 承认相近历史综述，再解释更广覆盖、共同框架、贯穿例子及研究方向各增加什么读者价值。
7. 安排后文章节，使读者看见这些承诺在哪里落实。

这篇的贡献不是“领域没有生成方法”，而是读者尚缺怎样的综合与比较。统一例子的价值不只在形式整齐，而在固定情景后读者能跟踪并比较方法变化。若新综述没有这个需求，就另找自己的组织理由。

U2 首段先定义对象，第二段才收束具体需要。U1 也没有与它相同的引言 roadmap。两篇本身就不能支持固定八段、固定首段末 urgency 或每篇逐节介绍的规则。

## 用到新稿时，先做一个具体的判断

**从哪里开始？** 会议中她对续作要求直奔这篇的起点，不再复述前一篇的长历史；但又要求解释读者不可能自动知道的 previous work。[T1d、T1h] 据当前问题，选择读者最短的进入路径。

**接下来为什么需要这一段？** 如果上一段已经说“实际数据有限”，下一段再举几个有限的例子，可能没有推进。把真正的新层次写出来：限制来自什么条件，旧法怎样处理其中一部分，还有哪一步没有覆盖。[T2]

**方法什么时候出现？** 读者应先理解前一路径到哪里为止，以及剩下的不足为什么需要本文的操作。续作尤其先交代前作的能力与实际待改进处；不能省掉前作解释，直接宣称新组件更好。[T1d、T1h]

**新稿是综述还是实证？** 综述要解释组织与比较如何帮助读者；实证要解释操作如何应对具体条件及用什么证据验证。两类都可以承认已有工作，再说明本文多做什么，材料与证明责任各不相同。

构思时用几句普通话把上述意思讲通，再写英文。表格只在帮助作者比较段落功能时使用，不是每次起草的必交产物。事实够用就给正文，缺的事实只在会改变结构或结论的地方提出。
