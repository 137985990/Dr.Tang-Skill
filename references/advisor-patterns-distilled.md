# 唐老师偏好精炼库

这个文件是唐老师审稿偏好的结构化存档，基于历次会议录音和聊天记录。  
用途：每次提炼出新规律时，在这里更新。SKILL.md 里的 Known Patterns 与本文件保持同步。

**最后更新：** 2026-04-28  
**数据来源：** 40+ 次会议录音转写文本（含 audio1688366793）

## 高置信度规律（3 次以上）

### 逻辑层面

| 编号 | 规律 | 原话 / 依据 |
|---|---|---|
| P1 | 每段必须有且只有一个核心论点 | "你没把一句忠心思想递给我" |
| P2 | 段与段之间不能有逻辑跳跃 | "这个跳跃太怪了" |
| P3 | 事实描述 ≠ 问题陈述，必须说清楚为什么是问题 | "Something happening is not a problem, that's a fact" |
| P4 | Introduction 第一段末尾必须有 urgency | "你第一段的结尾就应该说 practical deployment 才是 urgent need" |
| P5 | Related work 不是陈述问题的地方 | "问题在 introduction 里说了，related work 不要再说" |
| P6 | Related work 里每篇引用必须用自己的话解释 | "用你的理解后的语言描述，给没有背景的人看" |

### Claim 精确性

| 编号 | 规律 | 原话 / 依据 |
|---|---|---|
| L1 | 泛化断言必须有 citation 或缩小范围 | "全世界所有三色都被你打了一枪" |
| L2 | 强 claim 不能靠自己说，必须有文献支撑 | "这句话多么 strong，你不能自己说出来" |
| L3 | 不同性质的问题不能混为一谈 | availability ≠ degradation，这是高频错误 |

### Reviewer Response

| 编号 | 规律 | 原话 / 依据 |
|---|---|---|
| R1 | 每条评论都必须回应 | 多次强调，即使不同意也要正面回答 |
| R2 | 感谢语只在末尾出现一次 | 不能在每条 response 前面都说谢谢 |

### 发稿流程

| 编号 | 规律 | 原话 / 依据 |
|---|---|---|
| S1 | 发之前必须通读，读两遍可能不够 | "你这篇文章读了几遍？" |
| S2 | 同类错误不能重复出现 | "这种事情一定要放在心上" |

## 中置信度规律（2 次）

| 编号 | 规律 | 说明 |
|---|---|---|
| T1 | 批评他人方法要 diplomatic，但不模糊 | "has room for improvement" 而非 "has a deficit" |
| T2 | 批评自己方法用 limitation，不用 failure | 多次出现，但部分是情境性的 |
| L4 | 特定术语用法有严格要求 | missing modality / transform vs augment / impractical 等 |
| P7 | 设计决策的 justification 放在 methodology，不放 related work | 两次明确指出 |

## 使用说明

- 每次有新聊天记录 / 录音时，先用 skill 触发模式 A 提炼，再把新规律填到本表
- 置信度升级条件：同一规律在新材料中再次出现 → 从低升中，从中升高
- 规律废弃条件：在 3 次以上新材料中未再出现，或新材料明确矛盾 → 标注"存疑"
